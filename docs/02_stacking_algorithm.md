# 태현 위치 선택 + 재성 사후 평가

사용자 요청에 따라 위치를 고르는 규칙과 결과를 설명하는 지표를 분리했다.

## 1. 무엇이 바뀌었나

| 구간 | 현재 처리 |
|---|---|
| 후보 생성 | 태현 PR9 `3adb73c`의 `candidate_generation.py`로 복원 |
| 안전 후보 거르기 | 기존 지지·하중·CoG·경계 검사와 박스별 용량 유지 |
| 위치 순위 | 태현 `LayerPlacer` 원식. 로봇이 실행 가능한 첫 후보 선택 |
| 미래 배치 | `lookahead.placer: layer`, 실제 배치와 일치 |
| 재성 평가 | 선택 기록만 받아 주문 실행이 끝난 뒤 계산. 후보 재선택 없음 |
| 이전 혼합 점수 | 실험 코드 보존. 기본 `official_evaluation: false` |

낮은 높이·평탄도·접촉·지지·모서리의 기존 태현 계수를 그대로 쓴다. 정적 검사 값과 박스별 허용 하중을 변경하지 않았다. 0.3g 기둥 하드 필터를 되살리지 않았다.

N=5 행동 탐색, 기존 `j_proxy`, J의 2368초 가정, 7초 제한과 3계량+2카메라는 그대로다. 즉 **위치 선택 부분을 복원했으며, 전체 설정이 태현 원래 PR과 같다는 주장은 하지 않는다.**

## 2. 기록에서 찾은 원식

근거: `docs/jaesung/algorithm_v3/COST_FUNCTIONS.md` ②,
`ALGORITHM_V3_3.md` 4-2, `tools/prototypes/lookahead/lookahead.py`의 `Scorer.cost`.

```text
C = E - φS(S) - φL(L)                 # 작을수록 좋음
φ(x;t,a,b) = a*min(x,t) + b*max(0,x-t)
φS(S) = φ(S; .75, 20, 2)
φL(L) = φ(L; .5, 8, .5)
S = .20*support + .25*interlock + .40*tilt + .15*side
L = clip(1-max_load_ratio, 0, 1)
E = 2*z/H + 2*top/H + 2*rough + 1.5*void
    + 4*corner + 1.5*block + .5*floor
```

기준 아래에서는 개선에 큰 점수를 주고, 기준 위에서는 증가폭을 줄이는 **구간 선형의 비선형식**이다. 이 식은 S와 L에 적용된다. 공간 항목은 선형 가중합이다. 원문은 작업시간 T의 시제품 누락을 명시한다. 공식 5항목 전체에 완성된 옛 비선형식이 있었다고 표현하지 않는다.

기존 0.75 선택 실험 이력은 보존한다. 주변값 동등성이나 최적성은 입증되지 않았고, 나머지 비중·문턱값은 가정이다. 원래 코드의 팔레트 가장자리를 벽처럼 취급하던 오류는 복원하지 않았다. 따라서 원래 산식을 쓰되 기하 입력은 그 오류가 수정된 모델이다.

## 3. 공식 5항목 출력

| 항목 | 평가에 기록하는 내용 | 해석 |
|---|---|---|
| 적재율·공간 | 부피 채움률, 공간 7개 특징, E | E와 실제 주문 전체 적재율은 다른 지표 |
| 패턴 생성·작업시간 | 전체 결정 실측 초, 기존 로봇 예상 초 | 실제 운반시간으로 혼동하지 않음 |
| 무게중심·하중분포 | CoG 좌표, 최대 하중 사용률, L·φL | 최대 사용률은 하중분포 전체를 대변하지 않음 |
| 지지·낙하·붕괴 | 지지·맞물림·기울어짐 근사·옆면, S·φS | 기둥 전체 운반 안전성은 미검증 |
| 순서 실행 가능성 | 선택 동작의 로봇 검사 결과·경로 여유·실행 보고 | 한 동작 합격은 주문 전체 실행 성공이 아님 |

`legacy_cost`는 위 옛 후보 식의 값이다. **5항목 총점·공식 점수·성공 확률이 아니다.** 시간과 실행 가능성에 새 임의 비선형 계수를 만들지 않았다. 기록이 없으면 `null`과 이유를 남긴다.

## 4. 실행과 평가

ROS의 `merged_algorithm.launch.py`는 이제 기본 `ranker=layer`를 쓴다. ROS 자체를 이번 작업에서 실행한 것은 아니다.

가상 런타임에서도 `--ranker layer`와 통합 설정을 쓴다. 아래 검수 스크립트는 선택 직후 입력을 저장하고, 주문 실행이 끝나거나 제한 시간에 도달한 뒤에만 평가식을 계산한다. 평가 중에는 IK·후보 생성·탐색을 호출하지 않는다. 선택된 후보에 대한 정적 기하 검사는 독립 백엔드에서 재계산한다.

```bash
python tools/algorithm_integration/quick_runtime_audit.py \
  --dataset /absolute/path/to/dataset \
  --output /absolute/path/to/new-audit \
  --commit CURRENT_COMMIT --ranker layer --limit 60 --ids S0001
```

출력 `selected_step_evaluations`에 원자료 `input`과 다섯 항목 `evaluation`이 함께 들어간다. 이 평가 출력은 검수 스크립트에 연결했으며, ROS 명령에 자동 발행되는 평가 기능은 아니다. `PARTIAL_REPACK`의 중간 동작별 평가가 없으면 누락으로 남기며 새 박스 배치 점수를 대신 넣지 않는다.

별도로 기록한 입력 JSON에도 같은 식을 적용할 수 있다.

```bash
python tools/algorithm_integration/evaluate_five_metrics.py \
  --input selected-records.json --output evaluated.json
```

평가용 스냅샷 저장 비용은 결정 시간 밖이고 검수 주문의 벽시계 시간 안이다. 점수 계산 시간은 `offline_evaluation_s`로 따로 기록한다. 부분 적재율을 주문 완료 평균으로 사용하지 않는다. 같은 검수 중 시뮬레이션은 하나만 실행한다.

## 5. 검증 범위

원식 계산, 누락값 처리, 태현 후보 생성 복원, 진입점 설정, 선택과 평가 분리 검사 46개가 통과했다. 단일 합성 명령의 기존 로봇 모델 검사도 포함한다. 실제 운반 시험이나 주문 전체 성능 시험을 대신하지 않는다. 이번 구성의 평균 적재율과 전체 결정 7초 충족률은 아직 측정하지 않았다.

### 수정한 문제

1. **시작 준비 실패 은폐:** 환경 등록·READY 준비가 실패해도 셸의 `|| true` 때문에 계속 진행했다. 이제 준비 명령 실패 시 실행기를 시작하지 않고 비정상 종료한다.
2. **실패를 성공 상태에 반영:** MoveIt 명령은 종료코드 0과 PASS 로그가 모두 있어야 성공이다. NG 이동 실패 시 `done`·성공 결과를 기록하지 않으며, 팔레트 교체 실패 시 내부 팔레트 상태를 초기화하지 않는다.
3. **실행 결과 전달:** 실행기 정상 완료 0 / 실패 1 / 사용자 중단 130을 셸까지 전달한다. 작업셀 `summary.json`에 `status`와 `exit_code`를 기록하고, 실패 시 `RUN DONE`을 출력하지 않는다. 종료 시 컨베이어 정지를 명시적으로 요청한다.
4. **결정 시간 보고 기준:** 기존 보고서는 현재 상한이 8초인데도 7초 초과 수만 제공했다. `decisions.budget_s`, `over_budget`, 요약의 `decision_budget_s`, `decision_over_budget`을 추가했다. `over_7s`는 이전 결과와의 호환을 위해 유지한다. 알고리즘 제한이나 초과 명령 사용 정책은 바꾸지 않았다.
5. **재현 정보:** 가상 실행 `summary.json`의 메타데이터에 `--visible` 등을 반영한 실제 설정과 로봇 검사 설정을 보존한다. README와 Gazebo 문서에서 가상 로봇 시간과 실제 MoveIt 시간을 구별하고 오래된 컨베이어 설명을 정정했다.

### 가상 주문 실행과 재개 방법

전체 테스트가 끝난 후 아래 명령 하나만 실행했다. 다른 Gazebo나 성능 실험을 동시에 실행하지 않았다. 주문당 35초는 사용자의 **이번 작업 10분 제한을 지키기 위한 검증 중단 시간**이며, 제품의 결정 상한 8초와는 별개이다. 시간 제한으로 중단한 주문은 전체 적재·적재율 검증 완료로 세지 않는다.

```bash
python3 -u -m pipeline.run --output runs/handoff_20261010_fast_n3 \
  --boxes 40 --per-family 1 --visible 3 --wall-limit 35 --no-dashboard
```

### Claude ClientPayloadError

- 사용자 오류는 응답 본문 수신 중단으로 보고됐다. 근본 원인이 서버·중간 네트워크·압축 중 어디인지는 확인하지 못했다.
- 기존 `content.read(n)`은 EOF 이전 부분 본문만 반환할 수 있어, chunk를 EOF까지 읽도록 수정했다. 256 KiB 제한은 유지한다.
- 압축 협상을 `Accept-Encoding: identity`로 요청하고 `stream: false`를 명시한다. `ClientPayloadError`·`ServerDisconnectedError`만 1회 재시도한다. 두 시도 합계는 기존 120초 안으로 제한한다.
- HTTP 인증 오류와 인증서 검증 오류는 재시도하지 않으며 TLS 검증을 끄지 않는다. 실제 유료 API 호출은 하지 않았다. 로컬 HTTP 서버에서 잘린 본문 → 정상 응답 복구, 계속 끊김, 401, 공유 시간제한, SSL 실패를 검증했다.
